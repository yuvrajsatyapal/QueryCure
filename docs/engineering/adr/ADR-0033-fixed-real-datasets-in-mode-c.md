# ADR-0033: Fixed real datasets in Mode C, beside the generated workloads

- Status: Accepted (2026-11-06). Implemented and verified locally, including against the local sandbox and metadata servers; not deployed. No benchmark has been run on it.
- Area: Benchmark / Workloads
- Related: [ADR-0007](ADR-0007-sandbox-template-clones.md), [ADR-0015](ADR-0015-canonicalization-finalization-integrity.md), [ADR-0024](ADR-0024-deterministic-mode-c-evals-measurement-fixtures.md). ADR-0034 is reserved for the deferred audit-completeness decision (per-caller enforcement versus enforcement inside `finalize_run`, see CURRENT_PHASE) and is not written.

## Context
All six Mode C workloads are generated by QueryCure from `generate_series` and a seeded hash. They prove the engine on data we shaped. Nothing shows the engine, the auditor and the reports on data we did not generate. The owner chose the UCI Online Retail II dataset (real UK invoice lines, December 2009 to December 2011, 1,067,371 rows, CC BY 4.0) for that.

Constraints that shaped the design:
- `orders_ecommerce` and the other five are referenced by frozen reports, recordings and replay tests (ADR-0015). A workload ID such as `orders_ecommerce@v1:sf=0.1:seed=42` and the template name derived from it must keep parsing and hashing identically.
- A reference must identify the exact data. A reference to a file is worthless if the file can change under it.
- The data cannot be committed (licence and size) and the worker container must not need it.
- Candidate SQL still runs only as `qc_bench`, in disposable clones of a template (ADR-0007).

## Options
1. **Replace `orders_ecommerce` with the real data.** Breaks stored workload IDs, recordings and replay of old reports. Rejected.
2. **Add the real data beside the generated workloads, as a new kind of workload.** Chosen.
3. **Make the generated data look more realistic.** Still our data. Rejected as the goal, not as a tool.
4. **Vendor the CSV in the repository.** Licence, 133 MB, and a stale copy risk. Rejected.

## Decision
A workload is either **generated** (`name@vN:sf=X:seed=N`, unchanged) or **fixed** (`name@vN:data=<12 lowercase hex>`).

- **Reference.** `online_retail_ii@v1:data=b3471c34b273`, where the identifier is the first 12 hex digits of the SHA-256 of the prepared CSV. The registry pins the **full** digest, the byte size, and the reconciliation facts. A reference whose identifier does not match the pin is refused. Generated workloads reject `data=` and fixed workloads reject `sf=`/`seed=`. The fixed form is matched with `fullmatch`.
- **Where the data lives.** A file outside the repository: `$QC_DATASETS_DIR` (default `~/Datasets/QueryCure`) / `online-retail-ii` / `online_retail_ii.csv`. It is produced from the official XLSX by `workloads/retail_prep.py`, which is tested on a synthetic workbook and reproduces the pinned CSV byte for byte from the official download.
- **Loading.** `load_fixed_dataset` opens the file with `O_NOFOLLOW`, refuses non-regular files, checks the exact size, and checks the full SHA-256, all on one descriptor and before any database statement. It then creates the table, streams the bytes through `COPY … FROM STDIN` (the path never reaches the server, so no server-file privilege is involved), hashes them again as they stream (a file changed after verification fails the load), runs `ANALYZE`, and requires the pinned reconciliation values to match exactly. It is one transaction: any failure leaves no table.
- **Schema.** One table, `retail_lines`: `line_id bigint PRIMARY KEY`, `source_sheet smallint`, `source_row integer`, `invoice_no text`, `stock_code text`, `description text` (nullable), `quantity integer`, `invoice_date timestamp`, `unit_price numeric(12,3)`, `customer_id integer` (nullable), `country text`. Only the primary key is indexed; candidate indexes belong to the arms.
- **Types.** `numeric(12,3)`: the file has 18 three-decimal prices (`0.001`) that `numeric(10,2)` would round. `timestamp` without time zone: the source has none, and labelling it UTC would invent information. This is a deliberate, limited deviation from the all-UTC rule: it applies to this table only and is stated in the report-facing dataset notes.
- **As published.** Duplicates, cancellations, negative quantities and prices, zero prices, and missing customer ids and descriptions are kept. `line_id`, `source_sheet` and `source_row` are provenance added by the preparation tool.
- **Template.** Built once, locally, by `python -m querycure.workloads build-template` (local sandbox hosts only). Fixed templates use their own builder tag `tpl-fixed@1`, so the names of generated templates do not change. The template digest includes the CSV digest. A missing template without its source raises `SandboxUnavailableError` with the command to run. A refused or failed build leaves no half-built database.
- **Visibility.** The catalog lists the dataset with its full `ref` and `requires_local_data`. The demo profile neither lists nor accepts it (there is no data directory on a hosted deployment).
- **Frozen things.** No change to report builders or renderers, canonicalization profiles, benchmark rules, migrations or recordings. Compatibility goldens (`tests/unit/workloads/test_ref_compatibility.py`) pin the string form, template name and generated data of the existing references.

## Trade-offs
- \+ Real data, content-pinned, with a load path that cannot silently use the wrong file.
- \+ Existing workloads, references and templates are byte-for-byte unchanged.
- − Trust on first use: UCI publishes no checksums, so the pinned digests are those of the file downloaded on 2026-11-06.
- − The data must be prepared on each machine that builds the template. The worker never needs it, but a fresh checkout cannot run the dataset until someone does.
- − The registry carries a dataset's full pin and reconciliation facts, so changing the dataset means a new `@vN`.
- − Mode C measurements still go through the sandbox network path. The transport floor (BENCHMARK_ENGINE §12) applies, and speed-ups on small, fast queries are lower bounds.
- − No eval case or recorded fixture exists yet: the Mode C recording needs a real model run, which was out of scope. Until then nothing asserts a verdict for this dataset.

## Consequences
- `WorkloadRef` has optional `scale_factor`, `seed` and `data_id`; exactly one form is valid.
- `WorkloadSpec` has `build` (generated) or `fixed`, not both. Code that generated SQL for every registered workload skips fixed ones.
- Documentation: [ONLINE_RETAIL_II](../../data/ONLINE_RETAIL_II.md) holds the source, licence, citation, checksums and quality notes.
